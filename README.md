# Podkop-custom-domains

## Два скрипта, одно поведение

В репозитории лежат две взаимозаменяемые реализации одного пайплайна:

| | `recon.sh` | `recon.py` |
|---|---|---|
| Запуск | `./recon.sh figma.com` | `uv run recon.py figma.com` |
| Массовое обновление | `./update-all.sh -j 3` | `uv run recon.py --all -j 3` |
| Зависимости-бинарники | subfinder, dnsx, curl, jq, dig | subfinder, dnsx, dig |
| Зависимости-пакеты | — | httpx (ставит `uv` сам) |
| Требует | bash 3.2+ | Python 3.14+, `uv` |

Имена выходных файлов, коды выхода, переменные окружения и retention guard — **одинаковые**. Можно гонять оба скрипта по одним и тем же папкам вперемешку. На `context7.com` они дают побайтово идентичный `all_domains.txt`.

Чем `recon.py` объективно лучше:

- **Обрезанный ответ certspotter не теряется.** В bash `jq ... 2>/dev/null` на битом JSON молча возвращает пустоту; в Python ошибка парсинга ловится и включается fallback-скрейп, который вытаскивает имена из частичного тела.
- **Мусор из URL-кодировки не попадает в кандидаты.** `recon.sh` скрейпит сырые строки CDX и порождает имена вроде `2fwww.xbox.com` (из `%2Fwww.xbox.com`); `recon.py` сначала декодирует проценты и даёт `www.xbox.com`.
- **Исчерпанная квота HackerTarget распознаётся.** Источник отдаёт `200 OK` с текстом `API count exceeded` в теле — bash засчитывает это как успех, Python отдельно это ловит и сообщает.
- Параллельность на `asyncio` вместо опроса `jobs -rp` в цикле со `sleep` (обходной путь ради bash 3.2, который несёт macOS).

`recon.sh` остаётся первичным и не требует ничего, кроме bash. Выбор — на вкус.

## recon.sh

Скрипт для пассивного сбора доменов и поддоменов сервиса. Агрегирует данные из 8 бесплатных источников (запрашиваются параллельно, с ретраями при сетевых сбоях), дедуплицирует и валидирует результаты через DNS.

Предназначен для формирования списков доменов для [Podkop](https://github.com/itdoginfo/podkop).

### Зависимости

| Инструмент | Установка | Назначение |
|---|---|---|
| `subfinder` | `brew install subfinder` | Пассивная разведка поддоменов |
| `dnsx` | `brew install dnsx` | DNS-валидация доменов |
| `curl` | встроен в macOS | HTTP-запросы к API |
| `jq` | `brew install jq` | Парсинг JSON |
| `dig` | встроен в macOS | DNS-запросы |

Если инструменты не установлены — скрипт установит их сам (`brew` на macOS; на Linux системные тулы `curl`/`jq`/`dig` ставятся через `apt`/`pacman`/`dnf`, а для `subfinder`/`dnsx` скрипт подскажет `go install ...`, т.к. для них нет системного пакета).

### Использование

```bash
chmod +x recon.sh

# Базовый запуск (результаты в ./recon-<domain>/)
./recon.sh context7.com

# С указанием директории вывода
./recon.sh xda-developers.com ./xda-recon

# Сравнить с предыдущим запуском в тот же output_dir (см. "Режим --diff" ниже)
./recon.sh context7.com ./recon-context7.com --diff
```

### Источники данных

Источники опрашиваются параллельно (фоновыми задачами), с ретраями при сетевых сбоях; результаты объединяются и дедуплицируются. Число попыток у каждого источника своё: ответ `4xx` (нужен ключ, либо нас уже throttle-ят) не ретраится вообще — внутри одного прогона он не изменится, а повтор `429` только углубляет лимит.

| # | Источник | Описание |
|---|---|---|
| 1 | **subfinder** | ~30 пассивных источников: VirusTotal, Shodan, HackerTarget, crt.sh и др. |
| 2 | **crt.sh** | Certificate Transparency логи |
| 3 | **Certspotter** | CT логи (резервный источник, работает когда crt.sh недоступен). Без `CERTSPOTTER_API_KEY` отдаёт ответ по капле и обрывается — берётся одна попытка на 20 с, результат частичный |
| 4 | **HackerTarget** | Публичная база DNS |
| 5 | **URLScan.io** | Публичные сканы веб-страниц |
| 6 | **Wayback Machine** | CDX API web.archive.org |
| 7 | **AlienVault OTX** | Passive DNS. **Требует `OTX_API_KEY`** — анонимный доступ теперь отдаёт `429`, без ключа источник пропускается |
| 8 | **RapidDNS.io** | HTML-скрейпинг публичной базы поддоменов (без API-ключа) |
| 9 | **dig** | MX, NS, TXT записи основного домена |

Также рассматривались **ProjectDiscovery Chaos** и **DNSDumpster**, но не были добавлены: Chaos индексирует только домены bug-bounty программ (не подходит для произвольного домена), а DNSDumpster теперь требует API-ключ — оба нарушают принцип "без ключей" этого проекта.

После сбора все кандидаты проверяются через `dnsx` — в итоговый файл попадают только домены, у которых есть A-запись в DNS. Проход ровно один: `all_domains.txt` вычисляется из вывода `dnsx -resp`, а не отдельным запуском, поэтому два файла не могут разойтись между собой.

#### Защита от обнуления списка (retention guard)

`dnsx` завершается с кодом `0`, даже когда не разрезолвил вообще ничего, — то есть затроттленный резолвер способен молча заменить рабочий список Podkop пустым файлом. Поэтому перед перезаписью считается, сколько доменов выжило: если новый список сохраняет меньше `RECON_MIN_RETAIN` процентов от предыдущего (по умолчанию 50), запись **отменяется**, старые файлы остаются нетронутыми, подозрительный результат кладётся в `all_domains.rejected.txt`, а скрипт выходит с кодом `3`.

Снимок `all_domains.prev.txt` тоже делается только после прохождения этой проверки — отбракованный прогон не может затереть последний хороший список.

Если падение настоящее (домены правда умерли), перезаписать принудительно: `--force` или `RECON_MIN_RETAIN=0`.

#### Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `RECON_MIN_RETAIN` | `50` | Минимальный процент доменов от предыдущего запуска, ниже которого результат отбраковывается |
| `RECON_DNSX_THREADS` | `100` | `dnsx -t`. Повышать осторожно: на 35k кандидатов `-t 300` втрое быстрее, но находит вдвое меньше доменов — публичные резолверы начинают резать запросы |
| `RECON_DNSX_RETRY` | `3` | `dnsx -retry` |
| `RECON_DNSX_RESOLVERS` | — | `dnsx -r`, список резолверов через запятую (по умолчанию системный) |
| `RECON_DNSX_RATELIMIT` | — | `dnsx -rl`, запросов в секунду |
| `RECON_SKIP_DEPCHECK` | — | `=1` пропускает проверку зависимостей |
| `OTX_API_KEY` | — | Включает источник AlienVault OTX |
| `CERTSPOTTER_API_KEY` | — | Полный (не обрезанный) ответ Certspotter |

### Файлы результатов

После выполнения в директории вывода (`./recon-<domain>/` по умолчанию):

```
recon-context7.com/
├── all_domains.txt          # Живые домены — использовать в Podkop
├── all_domains_with_ip.txt  # Живые домены с IP-адресами
├── all_raw.txt              # Все кандидаты до валидации
├── subfinder.txt            # Сырой вывод subfinder
├── crtsh.txt                # Сырой вывод crt.sh
├── certspotter.txt          # Сырой вывод certspotter
├── hackertarget.txt         # Сырой вывод hackertarget
├── urlscan.txt              # Сырой вывод urlscan
├── wayback.txt              # Сырой вывод wayback machine
├── alienvault.txt           # Сырой вывод alienvault otx
└── rapiddns.txt             # Сырой вывод rapiddns.io
```

При запуске с `--diff` дополнительно появляются `all_domains.prev.txt` (снимок предыдущего запуска), `all_domains.new.txt` (новые домены) и, если был предыдущий запуск, `all_domains.gone.txt` (пропавшие домены).

**Для Podkop использовать `all_domains.txt`** — он содержит только домены, которые реально резолвятся в DNS.

### Режим `--diff`

Флаг `--diff` сравнивает свежий результат с предыдущим запуском в том же `output_dir` (снимок берётся по файлу, а не по git), чтобы не пересматривать вручную весь список ради новых доменов:

```bash
./recon.sh context7.com ./recon-context7.com --diff
```

Если появились новые домены — они печатаются в разделе "Diff vs previous run", попадают в `all_domains.new.txt`, а скрипт завершается с кодом выхода `2` (удобно для скриптов вроде `update-all.sh`, см. ниже). Пропавшие домены пишутся в `all_domains.gone.txt` и отдельно проговариваются в выводе.

Коды выхода:

| Код | Значение |
|---|---|
| `0` | Успех, новых доменов нет |
| `2` | Успех, есть новые домены (только с `--diff`) |
| `3` | Прогон отклонён: ни один источник ничего не собрал, либо сработал retention guard. **Файлы не изменены** |

### Массовое обновление всех таргетов (`update-all.sh`)


`update-all.sh` перезапускает `recon.sh --diff` для каждой папки, перечисленной в `targets.conf` (карта `папка → домен(ы)`, включая многокорневые таргеты вроде `brawlstars-recon`, `github-recon` и `playstation-recon`), и в конце печатает список таргетов, где появились новые домены:

```bash
# Посмотреть, что будет запущено, без единого сетевого запроса
./update-all.sh --dry-run

# Реальное обновление всех таргетов (по умолчанию 3 таргета параллельно)
./update-all.sh

# Строго последовательно, как раньше (с паузой 5 с между таргетами)
./update-all.sh -j 1
```

`-j` не меняет число запросов к источникам, только скорость. В итоговой сводке отдельно перечисляются таргеты, которые **потеряли** домены, и таргеты, чей результат был отклонён retention guard'ом; при наличии отклонённых или упавших таргетов скрипт выходит с кодом `1`.

⚠️ Один прогон `update-all.sh` расходует общий дневной лимит источников (например, HackerTarget: 50 запросов/день) сразу на все таргеты — не запускай его чаще одного раза в день.

## recon.py

Self-contained скрипт с inline-метаданными PEP 723 — зависимости объявлены в шапке файла, `uv` разрешает их сам, никакого venv и requirements.txt заводить не нужно.

```bash
# Одна цель
uv run recon.py context7.com
uv run recon.py xda-developers.com ./xda-recon
uv run recon.py context7.com ./recon-context7.com --diff

# Все цели из targets.conf, 3 параллельно
uv run recon.py --all -j 3
uv run recon.py --all --dry-run

# Шебанг тоже работает
./recon.py figma.com
```

Первый запуск скачает Python 3.14 и `httpx`, если их нет (~несколько секунд), дальше стартует мгновенно.

Флаги и переменные окружения — те же, что у `recon.sh`: `--diff`, `--force`, `RECON_MIN_RETAIN`, `RECON_DNSX_*`, `RECON_SKIP_DEPCHECK`, `OTX_API_KEY`, `CERTSPOTTER_API_KEY`. Коды выхода те же: `0` / `2` (есть новые) / `3` (прогон отклонён), плюс `1` для `--all`, если какая-то цель упала или была отклонена.

Обратите внимание: `curl` и `jq` в зависимостях не нужны — их заменяют `httpx` и модуль `json`. В этом и смысл: битый или обрезанный ответ здесь порождает обрабатываемое исключение, а не молча проглатывается через `2>/dev/null`.

### Ограничения

- Все источники **бесплатны и не требуют API-ключей**, но имеют rate limits. Не запускай скрипт на один домен чаще чем раз в несколько часов.
- `crt.sh` периодически недоступен — в этом случае скрипт продолжает работу с остальными источниками.
- HackerTarget бесплатный tier ограничен 50 запросами в день.
- Скрипт собирает только поддомены указанного домена. Для поиска других TLD организации (`.io`, `.ai` и т.д.) — проверь вручную через `dig +short context7.io A`.
- Внутренние/служебные домены (staging, grafana, vpn и т.п.) попадут в `all_raw.txt` — не добавляй их в Podkop без необходимости.
